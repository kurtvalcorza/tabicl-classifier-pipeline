## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install or repository import (the previous pair's `git+https://github.com/kurtvalcorza/...` install at an immutable commit is gone: the module is carried instead). Section 2 of each notebook is `src/tabicl_classifier_pipeline/api.py` verbatim (one cell tagged `metadata.dimer.embedded_module`; the only rewrite makes `DEFAULT_WEIGHTS_DIR` working-directory-relative), Section 3 carries the model identity and the one-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins (`torch==2.11.0` is now installed from the pins rather than assumed runtime-provided). `metadata.dimer.generated_from` records the repository, the generating commit, the module SHA-256 and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py`, `tests/test_companion_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when a notebook is not byte-identical to the generator's output for its template.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entry that is absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes it and asserts the manifest digest equals the package's `BASE_MODEL_SHA256`; `TabICLClassificationPipeline.from_pretrained(weights_dir=WEIGHTS_DIR, ...)` constructs the upstream estimator on the verified file with `allow_auto_download=False`. The previous `CHECKPOINT_SOURCE = "DIMER ZIP"` option is replaced by the snapshot directory: place the pinned `.ckpt` there and nothing is downloaded.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/<stem>_input_manifest.json` with the schema, the observed structure of every table (dropped missing-target rows are counted, never hidden — DAT23; class counts and the majority-class share are observed), the verdict and one recorded rejection finding; `evaluation_report` (EVAL21) writes `outputs/<stem>_evaluation_report.json` — `sample-sanity` with `accuracy` / `balanced_accuracy` / `f1_weighted` / `log_loss` / `roc_auc` (the repository's own metric ids; see the note below on `pearsonr`, the independent-test block and the training-mean baseline in the E2E notebook (classical baselines and the blend are attached), `not-measurable` (with what labelled data would make the task measurable) in the companion.
- **Artifact-inference companion (§18):** the bundle is supplied from outside the execution (upload, or `ARTIFACT_ZIP_PATH` for executors), extracted member by member by `safe_extract_zip` only after path/symlink/size checks (never `extractall`), verified by `verify_artifact_bundle` and `validate_artifact_runtime`, and compared with the carried pinned base-model identity before any model state is reconstructed; reconstruction uses the bundled checkpoint with `allow_auto_download=False` (no network fallback); no bundle is created and no fine-tuning happens in the companion.
- Classification obligations (Notebook Specification §20.1): the class list and class counts are printed before the model runs and every holdout/test class must be present in the support rows (`align_to_schema` refuses unseen classes); the decision rule is `argmax` over uncalibrated class probabilities (no threshold is shipped); accuracy, balanced accuracy and weighted F1 are the discrete correctness measures, log loss and ROC-AUC the probability/ranking measures; exported `probability_<class>` columns keep the fitted class order in both JSON and CSV, and classical-baseline probabilities are aligned to that order with `align_probabilities` before blending.
- `USE_BYOD`, `RUN_FINE_TUNING` and `RUN_NEW_DATA_INFERENCE` default to `False` so the E2E sample path never opens an upload dialog and never trains.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.

## Main tutorial

- exact pinned `tabicl-classifier-v2-20260212.ckpt` acquisition through the manifest-driven snapshot (`stage_missing_files` + `verify_snapshot`)
- Breast Cancer Wisconsin sample (default), Wine (three classes), the pinned Palmer Penguins archive (mixed categorical/numeric, pre-split), or BYOD CSV / pre-split `train.csv`/`val.csv`/`test.csv`
- categorical-target validation with dropped-row counting, row/feature/class ceilings, class coverage and a stratifiability check (`validate_inputs`, `prepare_classification_table`, `align_to_schema`, `check_stratifiable`)
- pretrained in-context evaluation with accuracy, balanced accuracy, weighted F1, log loss, and ROC-AUC where defined (`classification_metrics`)
- optional `FinetunedTabICLClassifier` CUDA fine-tuning behind `RUN_FINE_TUNING` with holdout-only selection (`compare_metric`); independent test is evaluation only
- companion classical tree baselines (LightGBM and Random Forest) with holdout leaderboard and device latency
- in-memory post-hoc probability blending with strict label alignment (`align_probabilities`), holdout-accuracy maximisation and generalisation assessment
- `evaluation_report` with the majority-class baseline, the classical baselines and the blend attached
- optional new-data inference with `prediction` + `probability_<class>` columns behind `RUN_NEW_DATA_INFERENCE` (inference-mode `validate_inputs`)
- DIMER-style bundle export: checkpoint + training context + manifest (digests, sizes, payload allowlist, producer runtime)
- fresh reload through `safe_extract_zip` + `verify_artifact_bundle` with label-identity and probability-equivalence checks

## Artifact contract

TabICL remains an in-context learner after downstream fine-tuning. A deployable bundle therefore requires at minimum:

```text
checkpoints/best.ckpt
training_context.parquet
artifact.json
```

The inference-only notebook verifies internal digests, reconstructs the support context, and calls the ordinary TabICL estimator with `allow_auto_download=False`.

## Trust boundary

ZIP path checks prevent traversal and symlink extraction, but they do not make model deserialization trustworthy. Load only artifacts you produced yourself or obtained from a trusted source. When a known ZIP SHA-256 is available, compare it before extraction/loading.

The portable artifact also embeds the labelled training context. Treat the exported ZIP with the same dataset licence, access-control, retention, and disclosure requirements as the source training data.

## Runtime evidence
